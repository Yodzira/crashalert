Вопросы

Ядро WordPress и так шлёт письмо о фатале. Чем это лучше?

Письмо ядра приходит владельцу сайта, теряется в спаме и молчит о повторах и восстановлении. CrashAlert быстрее (Telegram за секунды), адреснее (виновник + что обновлялось), показывает «снова работает» и хранит историю.

Замедлит ли сайт?

Нет. На здоровом запросе — только чтение одной опции, суммарно ~5 мс. Алерт уходит из cron-очереди уже после отдачи страницы.

А если база данных недоступна?

Последнее событие пишется в файл в uploads/crashalert/ (папка закрыта .htaccess) и уйдёт в алерт при восстановлении.

Как установить?

Скачайте zip → Плагины → Добавить новый → Загрузить плагин → Активировать. В админке появится меню CrashAlert.

FAQ

WordPress core already emails me about fatals. Why this?

The core email goes to the site owner, lands in spam, and says nothing about repeats or recovery. CrashAlert is faster (Telegram in seconds), more specific (culprit + what was updated), shows "back up" notices, and keeps history.

Will it slow my site down?

No. On a healthy request it only reads one option — about 5 ms total. Alerts leave via a cron queue after the page is served.

What if the database is down?

The last event is written to a file in uploads/crashalert/ (folder blocked via .htaccess) and sent once the site recovers.

How do I install it?

Download the zip → Plugins → Add New → Upload Plugin → Activate. A CrashAlert menu appears in wp-admin.
